## Deviations / assumptions
- **pandas-3.0 compatibility convention (cross-laptop — see CONTEXT.md 2026-06-30 [DATA] note).** pandas 3.0 makes string columns the extension `StringDtype`, so `np.issubdtype(series.dtype, np.number)` raises `TypeError`. **ALL ML code uses `pd.api.types.is_numeric_dtype(series)` (and the `pd.api.types.*` family) — never `np.issubdtype` on a Series dtype.** The `.mlvenv` currently resolves pandas to 2.3.3 (a downstream lib pins `<3`), but ML code is written to run on **both** 2.3.x and 3.0.x so it stays portable across the DATA venv (3.0.3) and the ML venv. Verified: DATA suite = 100/100 on pandas 3.0.3 after the fix.
- Heavy deps are import-guarded via `ml/_optional.py` (HAS_* flags) so every module imports and core paths run even if an optional lib is missing; deep models (torch/PyG) are REAL because the stack installs cleanly.
