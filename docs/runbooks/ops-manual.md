# Hawk-Eye Operations Manual

> **Owner:** PLATFORM (Laptop 06) · **Task:** PLATFORM-40
> **Validated against blueprint:** **Part 30.2** (Observability & SRE), Part 18 (degradation),
> **Part 34.3** (ops manuals). Service/port map: **CONTEXT.md §7** (maintained by PLATFORM).
> **Golden rule:** **alert-only** — nothing in this manual auto-blocks money; the only automatic
> action the platform takes on failure is **degrade to rules-only** (Part 18 / 30.1).

The whole stack is driven from the root **`Makefile`** — `make help` lists every target. The
runtime is `docker compose`, layered into three include files
(`deploy/compose/docker-compose.{core,app,platform}.yml`) wired together by the root
`docker-compose.yml`. Image tags come from the **BOM** (`deploy/versions.bom.yaml`) via
`deploy/compose/.env` (regenerated by `make bom-env`); a CI gate (`bom-drift`) fails on mismatch.

## 1. The stack at a glance — 26 service containers, 3 layers

The full compose stack is **26 service containers** across three layers (CONTEXT.md §7 is the
authoritative service/port map):

- **`core`** (10) — data infrastructure: `kafka` (KRaft) + `kafka-init`, `schema-registry`
  (Apicurio), `flink-jobmanager`, `flink-taskmanager`, `redis`, `clickhouse`, `postgres`,
  `minio`, `feast`.
- **`app`** (7) — serving/identity/observability: `serving` (KServe-v2 stub → Triton),
  `backend` (FastAPI stub → real), `keycloak`, `mlflow`, `airflow`, `prometheus`, `grafana`.
- **`platform`** (9) — PLATFORM services: `degradation-switch`, `tee-attestation` (mock),
  `pam-shim` (mock), `vault` + `vault-init`, `governance-api`, `hitl-gate`, `otel-collector`,
  `alertmanager`.

## 2. Start / stop the stack (via `make`)

| Action | Command | What it does |
|---|---|---|
| **Regenerate env from BOM** | `make bom-env` | Rebuilds `deploy/compose/.env` image pins from `deploy/versions.bom.yaml` (runs implicitly before `up`/`config`) |
| **Bring up the FULL stack** | `make up` | core + app + platform (all 26 containers) |
| **Bring up core only** | `make core-up` | Kafka/Flink/Redis/ClickHouse/Postgres/MinIO/Feast/SchemaReg |
| **Bring up app only** | `make app-up` | serving/backend/Keycloak/MLflow/Airflow/Prometheus/Grafana |
| **Stop (keep volumes)** | `make down` | Stops + removes containers; **data survives** |
| **Stop + wipe volumes** | `make nuke` | **Destructive** — removes everything *including* volumes |
| **Validate compose renders** | `make config` | `docker compose config` over all three files |

**Cold start order:** `make core-up` → wait for core health → `make app-up` → `make up` (or just
`make up`, which brings everything up with `depends_on` healthchecks gating start order).

## 3. Health checks

| Action | Command | Notes |
|---|---|---|
| **Container status / health** | `make ps` | Shows each container's health state |
| **Tail logs** | `make logs` (or `make logs S=<service>`) | Filter to one compose service |
| **End-to-end smoke** | `make topology-smoke` | Flows a synthetic L0 event through the pipeline and asserts an **alert lands** (status=`open`, alert-only) |
| **Per-service liveness** | `GET /health` on the service port | Every service exposes `/health`; backend/governance-api/hitl-gate also expose `/metrics` for Prometheus |
| **Metrics** | Prometheus :9090, Grafana :3000 | Golden-signals + model-health dashboards (`observability/grafana-dashboards/`) |

Quick liveness probes (host):

```bash
curl -fsS http://localhost:8000/health      # backend
curl -fsS http://localhost:8093/health      # governance-api
curl -fsS http://localhost:8094/health      # hitl-gate
curl -fsS http://localhost:8092/health      # degradation-switch
curl -fsS http://localhost:9090/-/healthy   # prometheus
```

## 4. The degradation switch (continuity feature — Part 18 / 30.1)

If ML serving (:8001) is unhealthy, the pipeline **does not stop** — it **falls back to
L1-rules-only** via the `degradation-switch` (:8092). This is a *designed continuity feature*, not
an outage: alerts keep flowing, just from rules + transparent fusion.

| Action | Command |
|---|---|
| **Prove rules-only fallback** | `make degradation-demo` (kills ML serving, shows L1-rules continuity) |
| **Chaos test** | `make chaos` (kills a broker + a serving node; asserts the pipeline survives via degradation) |

This is verified by a unit test that includes the **alert-only invariant**
(`tests/test_degradation_switch.py`).

## 6. Secrets, residency & egress (operational guardrails)

- **Secrets** live in **Vault** (:8200, dev mode locally; `vault-init` seeds it). No real
  `NEAR_AI_API_KEY` is embedded anywhere — it is injected at runtime from the secrets manager.
- **Residency:** all data + compute stay **in-india** (region `ap-south-1` on the cloud pilot;
  on-prem in production). `make residency-check` asserts this over rendered manifests.
- **LLM egress** to NEAR AI (primary) / Groq (secondary) is **tokenized + TEE-attested only**;
  the narrative LLM never sees raw PII and **never makes a decision** (Part 25). If the gateway
  is down, narratives fall back to a deterministic Jinja template (the UI never breaks).

  [DR Failover Runbook](../../ops/dr/runbooks/failover-runbook.md); recovery objectives are in
